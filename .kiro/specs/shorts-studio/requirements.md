# Requirements — AI 숏폼 자동 수익화 스튜디오

## 소개

얼굴 출연과 직접 녹음 없이 AI 중심으로 숏폼 영상(YouTube Shorts, Instagram Reels, TikTok)을
제작·관리하는 로컬 스튜디오를 만든다. 가장 중요한 비기능 요구사항은 **저작권 및 플랫폼 수익화
정책의 준수**이며, 저작권 탐지 회피 기능은 구현하지 않는다. 시스템은 수작업을 최대한 줄이되,
콘텐츠 방향 승인과 최종 영상 검수는 사람이 수행한다.

이 문서는 EARS(Easy Approach to Requirements Syntax) 형식으로 수용 기준을 기술한다.

---

## 요구사항 1 — 저작권/라이선스 권리 관리 (최우선)

**사용자 스토리:** 콘텐츠 제작자로서, 모든 영상 소재의 권리 정보를 저장하고 검증하여, 권리가
확인되지 않은 소재가 제작에 사용되는 것을 방지하고 싶다.

#### 수용 기준
1. WHEN 소재가 등록되면 THEN 시스템은 다음 필드를 저장해야 한다: 원본 출처, 원저작자, 라이선스 종류, 상업적 이용 가능 여부, 편집/2차저작 가능 여부, 출처 표기 의무, 허락 증빙(파일/URL), 이용 만료일.
2. WHEN 소재의 상업적 이용 여부 또는 편집 가능 여부가 "불가" 또는 "미확인"이면 THEN 시스템은 해당 소재를 제작 파이프라인에서 자동으로 제외해야 한다.
3. WHEN CC 라이선스가 입력되면 THEN 시스템은 종류(CC0, CC BY, CC BY-SA, CC BY-NC, CC BY-ND 등)별로 상업적 이용 및 수정 가능 여부를 판정해야 한다.
4. IF 소재에 포함된 음악/인물 초상권/상표 등 별도 권리 항목이 "미확인"이면 THEN 시스템은 전체 소재를 사용 불가로 표시해야 한다.
5. WHEN 이용 만료일이 현재 날짜를 지나면 THEN 시스템은 해당 소재를 자동으로 사용 불가로 전환해야 한다.
6. THE 시스템은 "출처만 표기하면 사용 가능"이라고 판단해서는 안 된다(출처 표기와 이용 권리를 분리하여 판정).

## 요구사항 2 — 소재 수집 및 관리

**사용자 스토리:** 콘텐츠 제작자로서, 사용 가능한 영상/이미지/음악 소재를 수집하고 목록으로
관리하여, 제작에 바로 투입할 수 있는 안전한 소재 풀을 갖고 싶다.

#### 수용 기준
1. WHEN 사용자가 소재를 추가하면 THEN 시스템은 파일 또는 URL과 요구사항 1의 권리 메타데이터를 함께 저장해야 한다.
2. THE 시스템은 소재를 유형(영상/이미지/음악/효과음)과 사용가능 상태로 필터링하여 조회할 수 있어야 한다.
3. WHEN 권리 검증을 통과한 소재만 THEN 제작 단계에서 선택 가능해야 한다.
4. THE 시스템은 상업적 이용이 허용된 무료 스톡/음원 소스를 출처로 등록하는 것을 지원해야 한다.

---

## 요구사항 3 — 영상 자동 제작 (MVP 핵심)

**사용자 스토리:** 콘텐츠 제작자로서, 선정한 주제로 대본·내레이션·자막·영상을 자동 조립하여,
사람이 처음부터 편집하지 않아도 완성도 있는 9:16 숏폼을 얻고 싶다.

#### 수용 기준
1. WHEN 주제가 입력되면 THEN 시스템은 독창적인 한국어 대본(도입부 포함)을 생성해야 한다.
2. WHEN 대본이 확정되면 THEN 시스템은 AI TTS로 한국어 내레이션 음성을 생성해야 한다.
3. WHEN 내레이션이 생성되면 THEN 시스템은 음성과 동기화된 자막을 생성해야 한다.
4. WHEN 소재·음성·자막이 준비되면 THEN 시스템은 FFmpeg로 9:16, 1080×1920, MP4(H.264) 영상을 조립해야 한다.
5. THE 시스템은 상업적 이용이 허용된 배경음악만 사용해야 한다(요구사항 1 게이트 적용).
6. WHEN 영상이 생성되면 THEN 시스템은 제목, 설명, 썸네일 문구, 해시태그를 함께 생성해야 한다.
7. THE 시스템은 두 가지 버전을 각각 별도 구성으로 생성해야 한다: (A) 25~45초, (B) 65~90초. 단순 길이 조절이 아니라 시청 흐름에 맞춘 별도 구성이어야 한다.
8. IF 사용 가능한 소재가 부족하면 THEN 시스템은 제작을 중단하고 부족한 소재를 보고해야 한다.

---

## 요구사항 4 — 자동 품질 검수

**사용자 스토리:** 콘텐츠 제작자로서, 업로드 전 자동 검사를 통해 결함이 있는 영상을 걸러내고 싶다.

#### 수용 기준
1. WHEN 영상이 완성되면 THEN 시스템은 다음을 검사해야 한다: 저작권/라이선스 증빙 존재, 자막 오타(가능 범위), 음성·자막 싱크, 검은 화면/깨진 프레임, 음성 볼륨, 영상 길이, 해상도.
2. WHEN 대본이 생성되면 THEN 시스템은 독창성(기존 소스와의 실질적 중복 위험)을 점검해야 한다.
3. IF 검사 항목 중 하나라도 실패하면 THEN 시스템은 영상을 "수정 필요" 또는 "보류"로 표시하고 통과시키지 않아야 한다.
4. THE 시스템은 플랫폼별 AI 생성 콘텐츠 표시 의무 체크 항목을 제공해야 한다.
5. THE 시스템은 수익화 가능성을 보증한다고 표시해서는 안 된다.

---

## 요구사항 5 — 트렌드/인기 콘텐츠 분석

**사용자 스토리:** 콘텐츠 제작자로서, 공식 API로 확인 가능한 데이터를 기반으로 인기 주제를
파악하고 새로운 아이디어를 제안받고 싶다.

#### 수용 기준
1. THE 시스템은 공식 API(예: YouTube Data API)로 확보 가능한 데이터만 수집해야 한다: 주제, 영상 길이, 조회수, 좋아요/댓글 수, 제목, 해시태그.
2. IF 공식 API로 확인할 수 없는 지표(예: 시청 완료율, 3초 이탈률)가 요청되면 THEN 시스템은 추측하지 않고 "확인 불가"로 표시해야 한다.
3. WHEN 분석이 완료되면 THEN 시스템은 하루 최대 10개의 새로운 아이디어를 제안해야 한다.
4. THE 시스템은 타인의 대본이나 영상 구성을 실질적으로 복제하지 않고 일반적 흥행 패턴만 참고해야 한다.

---

## 요구사항 6 — 업로드 자동화 / 패키지 생성

**사용자 스토리:** 콘텐츠 제작자로서, 승인한 영상을 플랫폼에 게시하거나, 자동 게시가 불가능하면
수동 업로드용 패키지를 받고 싶다.

#### 수용 기준
1. IF 플랫폼 API 권한/승인이 없으면 THEN 시스템은 자동 업로드가 가능한 것처럼 구현하지 말고, 영상+메타데이터+해시태그가 담긴 수동 업로드 패키지를 생성해야 한다.
2. WHEN 업로드가 시도되면 THEN 시스템은 성공/실패를 기록하고 중복 업로드를 방지해야 한다.
3. THE 시스템은 플랫폼별 게시 상태와 예약 일정을 표시해야 한다.
4. WHEN 초기 운영 중이면 THEN 시스템은 사용자의 최종 승인을 받은 영상만 게시해야 한다.

---

## 요구사항 7 — 관리자 대시보드 (한국어)

**사용자 스토리:** 초보 운영자로서, 전체 제작 현황과 검수 결과를 한눈에 보고 영상을 승인하고 싶다.

#### 수용 기준
1. THE 대시보드는 한국어로 제공되어야 한다.
2. THE 대시보드는 다음 화면을 제공해야 한다: 제작 현황, 트렌드 분석, 아이디어 목록, 제작 대기열, 진행 상태, 저작권 검수 결과, 완성 영상 미리보기, 업로드 승인·예약, 플랫폼별 실적, 비용.
3. WHEN 사용자가 영상을 승인하면 THEN 시스템은 해당 영상만 게시/패키지 대상으로 전환해야 한다.
4. THE 대시보드는 깔끔하고 일관된 UI를 가져야 한다.

---

## 요구사항 8 — 성과·비용 분석 및 운영 최적화

**사용자 스토리:** 콘텐츠 제작자로서, 실제 성과와 비용을 기록하여 아이디어·대본 품질을 개선하고 싶다.

#### 수용 기준
1. THE 시스템은 확인 가능한 플랫폼 실적 데이터만 실적으로 표시하고, 추정치는 별도로 구분 표기해야 한다.
2. THE 시스템은 API/TTS/영상 생성 등에서 발생한 비용을 영상별로 기록해야 한다.
3. WHEN 성과 데이터가 쌓이면 THEN 시스템은 성과가 좋은 주제/구성을 분석하여 제시해야 한다.
4. THE 시스템은 동일 영상의 반복 대량 생산을 방지하는 중복 점검을 제공해야 한다.

## 비기능 요구사항 (전역)

1. **저작권 회피 금지:** 화면 반전/배속/크롭/필터를 이용한 저작권 탐지 회피 기능을 구현하지 않는다.
2. **보안:** API 키/비밀번호는 `.env`로 관리하며 소스코드/저장소에 포함하지 않는다.
3. **정직성:** 실제로 실행·검증된 기능만 완료로 표시한다. 한 번에 완성된 것처럼 꾸미지 않는다.
4. **운영 환경:** Windows PC에서 동작해야 한다(크로스플랫폼 Python 기준으로 개발).
5. **무결성:** 기존 사용자 파일/프로젝트를 손상시키지 않는다.
6. **무료 우선:** 가능한 한 무료·오픈소스 도구를 우선 사용한다.
